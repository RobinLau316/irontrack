# IronTrack 旧数据兼容与页面恢复设计

日期：2026-09-01  
状态：已实现并通过本地验收，待线上发布
对应 PRD：`docs/superpowers/specs/2026-08-28-irontrack-prd.md`

## 1. 问题

- 已有用户可能无法生成今日计划。
- “训练体系”页面可能空白，切换后底部导航位置异常。
- “我的”页面仍保留当前没有用途的知识库入口和占位内容。

线上新建用户可以正常生成计划和打开训练体系，故障集中在已有用户的本地数据兼容。旧备份或旧版本数据可能缺少 `cycle_variants`、`core_locks`、`training_phase` 等字段；当前读取逻辑会把已存储的 `null` 当作有效值，随后在计划生成和训练体系渲染时发生异常。

## 2. 目标

1. 自动补齐缺失或无效的运行状态，不要求用户清除浏览器数据。
2. 优先保留个人档案、训练历史、身体记录、有效计划和进行中训练。
3. 即使 AI、网络或兼容数据异常，仍能生成本地备用计划。
4. 页面渲染异常不能留下空白页，也不能改变底部导航位置。
5. 删除“我的”页面中的知识库入口、占位内容和专用样式。

## 3. 数据兼容设计

- 登录后统一执行数据规范化，再渲染任何业务页面。
- `profile` 与默认档案合并；有效用户值优先保留。
- `plan` 必须包含非空训练日，训练日必须具有名称、部位和动作数组；无效时按当前分化模板恢复计划骨架。
- 列表字段不是数组时恢复为空数组；周期索引转换为非负整数。
- `cycle_variants`、`core_locks`、`training_phase` 缺失或为 `null` 时补默认值，合法的已有值继续保留。
- `setup_draft` 补齐默认结构，并保证不适部位为数组。
- 仅覆盖缺失或结构无效的字段，不清空训练历史和身体数据。
- 如必须替换非空的无效数据，先在当前用户命名空间保存一次兼容恢复快照。

## 4. 生成与页面异常处理

- 生成计划前再次检查运行状态，避免长时间打开页面后使用到无效状态。
- 生成按钮使用 `try/catch/finally`：无论成功或失败都恢复可点击状态。
- AI 不可用时继续沿用本地备用计划；本地生成异常时先自动修复数据并重试一次。
- 训练体系渲染前完成数据检查；意外失败时显示可恢复提示和重试按钮，不保留空白页面。
- 页面切换无论渲染是否成功，都清除键盘专用状态、恢复滚动顶部并保持固定导航安全区。

## 5. “我的”页面精简

- 删除“知识库”标签。
- 删除知识库占位数据、渲染分支和专用样式。
- “我的”页面直接展示个人档案、训练偏好、器械、AI 设置和本地备份。

## 6. PRD 影响

兼容修复不是需求冲突。现有 PRD 已要求：AI 异常时使用本地计划、发布不得破坏原有数据、备份恢复正常、底部导航保持稳定；当前故障属于实现未完整满足既有要求。

删除知识库与 V1.1 原有“不得删减现有功能入口”存在局部冲突。按用户 2026-09-01 的明确变更，PRD 增加例外：删除“我的 → 知识库”占位入口及内容，其他功能入口继续保留。

## 7. 验收

1. 全新用户和已有用户均可生成今日计划。
2. 缺少或存有 `null` 的兼容字段时，系统自动修复且训练历史仍保留。
3. 无 API Key、无效 API Key或网络失败时可进入本地计划预览。
4. 训练体系正常显示；意外数据错误时出现恢复提示，不出现空白页。
5. 320×568、375×667、390×844 下底部导航固定在安全区底部。
6. “我的”页面不再出现知识库入口和内容。
7. 进行中训练、训练历史、导出备份和刷新恢复完成回归。
