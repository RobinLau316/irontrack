# IronTrack V1.1 UI 视觉改版设计规格

日期：2026-08-31
状态：已实现、验收并上线
对应 PRD：`docs/superpowers/specs/2026-08-28-irontrack-prd.md` 第 14 章

## 1. 目的与范围

本设计在保持 IronTrack 现有训练功能、数据和使用闭环不变的前提下，重做视觉系统、页面排版、底部导航和训练操作区。目标是形成“高级运动品牌 + 专业个人训练工具”的统一体验。

本轮包含：

- 登录、首页、训练体系、生成前设置、计划预览、正式训练、休息、反馈、完成、数据和我的页面。
- 颜色、字体、间距、图片、分隔、按钮、表单、提示、动画和响应式规则。
- 底部导航遮挡问题的修复和窄屏专项验收。

本轮不包含：

- PPL、动作库、A/B 轮换、AI 提示词和渐进负荷规则调整。
- 新增浅色模式、云同步、教练端或多人功能。
- 修改本地存储结构或迁移历史数据。
- 重写早期 Next.js 原型；当前发布入口仍为 `index.html`。

## 2. 设计基调

### 2.1 视觉命题

深夜训练场中的高对比力量感：真实训练照片负责情绪，近黑界面负责专注，荧光绿只用于推动用户进入下一步。

### 2.2 品牌颜色

建议基础色值：

| 用途 | 色值 | 说明 |
|---|---|---|
| 页面背景 | `#0B0B0A` | 近黑、略带暖色 |
| 一级表面 | `#171714` | 表单、必要容器和固定操作区 |
| 分隔与描边 | `#292925` | 低对比结构线 |
| 主文字 | `#F3F2EA` | 暖白，降低纯白刺眼感 |
| 次文字 | `#92948D` | 说明、单位和非当前状态 |
| 品牌强调 | `#D9FF43` | 主按钮、进度、选中与关键数字 |

荧光绿是唯一品牌主色。错误、警告、成功和不适反馈可使用红、橙、绿等语义色，但面积应小，并只用于表达状态。

### 2.3 字体与数字

- 使用系统无衬线字体栈，避免网络字体成为加载依赖。
- `IRONTRACK` 使用大写、粗字重和收紧字距。
- 页面标题使用粗字重和紧凑行高；正文保持正常字距和可读行高。
- 重量、次数、计时和统计使用等宽数字特性，避免数值变化时跳动。
- 字号使用响应式范围，不以固定超大字号换取冲击感。

### 2.4 图片

- 登录页和今日首页使用低光、真实、单人力量训练照片。
- 人物应正在执行明确训练动作，面部不作为视觉中心。
- 图片不得包含第三方品牌、嵌入文字、界面或明显畸变。
- 正式图片输出为本地 WebP；必要时提供 JPEG 兜底。单张目标不超过 400KB。
- 图片上方文字必须处于稳定暗区，并通过渐变遮罩保证对比度。

### 2.5 文案

- 品牌语气简短、有力量，不使用大段励志文字。
- 首页可以使用“今天，向上突破。”等一句式文案。
- 训练、数据和设置页面优先使用功能性文字。
- AI、本地备用计划、错误和数据边界必须直白说明，不用品牌文案掩盖状态。

## 3. 页面设计

### 3.1 登录页

- 使用全屏训练照片与深色遮罩。
- 品牌名置于上部安全区；已有用户名和新用户名输入置于下部安全区。
- 输入和进入按钮形成一个明确操作组，键盘打开后仍可见。
- 不改变现有本地用户名切换逻辑。

### 3.2 今日首页

- 采用“品牌与效率平衡”布局，而非纯海报或纯数据仪表盘。
- 主视觉约占首屏一半，包含推荐训练日、A/B 方案、短文案和主要入口。
- 主视觉下方优先展示本周完成情况、连续训练、训练阶段和上次训练摘要。
- 减少小卡片拼贴；数据可以通过两列排版、分隔线和字号区分。
- 继续保留训练体系和数据页入口，但降低其相对主训练入口的权重。

### 3.3 训练体系页

- PPL 周期用横向时间线表达当前、完成和下一训练日。
- 当前阶段、核心动作锁定和 A/B 状态在周期下方分区展示。
- 训练原则使用短列表，不使用多个同级装饰卡片。
- 锁定、解除锁定和开始新阶段保持现有功能和确认逻辑。

### 3.4 生成前设置

- 训练部位、身体状态、时间和环境各自形成清楚的选择组。
- 选中项使用荧光绿描边或填充；未选中项保持低对比。
- 不适部位和避开动作与常规选项拉开层级，健康提示使用语义警示色。
- 未完成必填项时，在对应分组附近提示，不只在页面底部显示错误。

### 3.5 计划预览

- 页面顶部显示计划来源、训练日、A/B 方案、动作数量、时间和环境。
- 核心动作优先展示，使用明确“核心”标识；辅助动作以紧凑列表连续排列。
- 组数、次数、重量和休息保持直接编辑；标签和输入必须在窄屏完整显示。
- 锁定和替换属于次要动作，不能压过“确认计划并开始”。
- 页面底部为确认计划预留足够空间，固定导航不得遮挡。

### 3.6 正式训练

- 采用“单组专注”布局：动作名称、目标、本组重量、本组次数、组进度、完成按钮。
- 重量和次数分别纵向排列，数字居中放大，两侧保留不小于 44px 的调整按钮。
- 直接输入能力保留；编辑值与完成记录使用同一数据校验规则。
- 长动作名称最多两行；关键数字按容器宽度自动缩放，单位始终完整显示。
- “完成本组”固定在导航栏上方；训练时无需下滑即可完成主要操作。
- “跳过当前动作”和“跳过剩余”保留，可降低权重或收纳到“更多操作”。

### 3.7 休息、反馈与完成

- 休息页以大号倒计时为中心，显示下一组或下一动作；跳过休息保持可见。
- 动作反馈使用四个清楚选项，选择后立即显示当前状态；备注为次要输入。
- 完成页以训练时长、动作完成量和关键表现为主，使用一次明确的完成动效。

### 3.8 数据页

- 首屏展示本周次数、总组数、容量和时长，避免分散成大量同级卡片。
- 核心动作趋势优先；图表颜色以荧光绿为主，多系列使用低饱和辅助色。
- 训练历史按时间排列，显示训练日、时长、动作数量和反馈摘要。
- 无数据时提供简短空状态和开始训练入口。

### 3.9 我的页面

- 按“身体资料、训练偏好、器械、AI 设置、本地数据”分区。
- 表单标签和当前值有清楚层级；保存按钮只在有修改时突出。
- API Key状态、测试结果和本地备份说明保持明确，不用装饰性文案。

## 4. 导航与固定操作区

### 4.1 底部导航

- 保留首页、训练体系、训练、数据、我的五个入口。
- 中央训练按钮保持突出，使用荧光绿圆形按钮；其他入口为低对比图标和文字。
- 导航高度、系统安全区和页面底部留白使用统一变量，禁止各页面自行估算。

### 4.2 已核实的遮挡问题

在当前版本 390×844 视口的正式训练页，页面位于顶部时：

- “完成本组”按钮范围约为 `y=755.5～812.5`。
- 固定底部导航范围约为 `y=773～844`。
- 两者重叠约 40px；两个次要按钮位于首屏之外。

新版必须移除该重叠。

### 4.3 新版安全规则

- 定义统一的导航高度、安全区和操作区高度。
- 正式训练主操作区固定在导航栏上方，并与导航保留可见间距。
- 页面正文底部留白至少覆盖固定操作区和导航栏总高度。
- 输入框获得焦点、虚拟键盘出现时，当前输入框自动保持在可视区域；必要时暂时收起固定操作区。
- 非训练页面的主按钮默认进入普通文档流，不因全局固定造成内容覆盖。

## 5. 动效

- 首页主视觉、标题、主要按钮和状态数据分层进入，总时长控制在约 700ms 内。
- 页面切换使用淡入和短距离位移；主要组件的进入顺序一致。
- 进度条和数字更新使用 180～350ms 过渡。
- 主要按钮按下、选项选中和完成记录提供清楚的缩放或颜色反馈。
- 不保留持续脉冲、无限闪烁等长期吸引注意力的装饰动画。
- `prefers-reduced-motion: reduce` 下关闭位移、缩放和分批进入，只保留即时颜色或透明度反馈。

## 6. 状态与错误处理

- AI 生成中、本地备用计划、API 连接失败、恢复训练和保存结果使用统一状态条。
- 错误提示靠近发生位置，并说明下一步；不能只改变颜色。
- 图片加载失败时显示近黑背景和完整文字，不影响进入训练。
- 原有本地计划兜底、训练恢复和数据校验逻辑保持不变。
- 任何 UI 失败都不得破坏本地训练记录或阻断已确认计划的执行。

## 7. 数据与兼容性

- 本轮不修改 `localStorage` 键、备份版本或训练数据结构。
- 所有现有用户数据直接由新版页面读取，不执行清空或覆盖式初始化。
- 进行中训练刷新后仍恢复动作、组数、实际重量、实际次数和休息状态。
- API Key继续使用独立本地键，不写入仓库，不加入普通备份。
- 图片和样式修改不得引入远程运行依赖。

## 8. 实施顺序

1. 建立颜色、字体、间距、圆角、导航高度和安全区变量。
2. 重构通用按钮、表单、状态条、分隔和页面进入动画。
3. 改造登录页与今日首页，并接入本地主视觉图片。
4. 改造训练体系、生成前设置和计划预览。
5. 改造正式训练、休息、反馈和完成页面，修复底栏遮挡。
6. 改造数据页和我的页面。
7. 执行功能回归、响应式测试、减少动态效果测试和线上部署验证。

## 9. 验收清单

### 9.1 视觉一致性

- 所有页面使用同一组背景、文字、强调色、间距和按钮规则。
- 首页和登录页主视觉正常加载；其他页面不出现无必要的大图。
- 不存在无意义卡片堆叠、多个竞争主色或持续脉冲动画。

### 9.2 响应式

- 在 320×568、375×667、390×844 视口下无横向滚动。
- 动作名称、82.5 等小数重量、次数、单位和按钮完整显示。
- 底部导航不覆盖内容；正式训练主按钮无需下滑即可操作。
- 虚拟键盘打开后，重量和次数输入框保持可见。

### 9.3 功能回归

- 现有用户登录和切换正常，历史数据仍可见。
- 无 API Key 时本地计划正常；有效 API Key 时 AI 计划仍通过校验。
- 计划预览的编辑、锁定、替换和确认正常。
- 正式训练的直接输入、加减、完成、休息、刷新恢复、跳过和反馈正常。
- 完成训练后 PPL、A/B、阶段、历史和数据统计正常更新。
- 备份导出不包含 API Key；导入成功和失败保护均正常。

### 9.4 动效与性能

- 动画有明显层次，但不延迟输入、计时或按钮操作。
- 减少动态效果设置生效。
- 首页图片压缩并本地加载；图片失败不阻断页面使用。
- 静态脚本检查、浏览器控制台检查和 GitHub Pages 线上核验通过。

## 10. 完成定义

只有同时满足以下条件，V1.1 UI 改版才算完成：

1. 主 PRD 与本设计规格中的视觉、页面和安全区要求全部实现。
2. 目标视口和主要训练闭环验收通过。
3. 既有本地数据和训练逻辑未被破坏。
4. 线上 GitHub Pages 已更新并能加载本地主视觉资源。
