# IronTrack 运行与发布手册

更新日期：2026-09-02

## 1. 本地运行

```bash
npm run dev
```

打开 `http://127.0.0.1:4173/`。修改 `index.html` 后刷新浏览器即可看到变化。

## 2. 静态检查

```bash
npm run build
git diff --check
```

`npm run build` 不调用早期 Next.js 原型，当前依次检查：

- `index.html` 的脚本语法和关键功能标记。
- 精选动作库数量、字段、中文名称、动作模式、器械和默认训练量。
- 207 份中文步骤、91 个旧动作映射、资源体积和上游媒体排除边界。
- 推拉腿在 30/45/60/90 分钟下的动作数量、三类环境、稳定轮换、结构平衡、AI 候选边界和非破坏式旧数据迁移。

阶段二已于 2026-09-03 发布并完成线上验收。以后涉及动作库版本或数据结构升级，仍须先导出现有备份再发布。

## 3. 浏览器冒烟测试

发布前至少验证：

1. 新建本地用户并进入训练页。
2. 选择身体状态、时间、环境、不适部位和避开动作。
3. 不设置 API Key 时可以生成本地备用计划。
4. 30 分钟生成 8 个动作，90 分钟生成 15 个动作。
5. 被避开的动作不会出现；不适部位对应动作模式会被过滤。
6. 计划预览可以锁定、替换和修改数字。
7. 正式训练中的重量和次数可以直接输入；次数左右按钮每次调整 1，重量沿用现有调整规则；输入为空时不会出现 `NaN`。
8. 完成一组后进入休息；刷新并重新选择用户后可以恢复，包括刚输入的重量和次数。
9. 完成动作后可以提交“轻松/合适/吃力/不适”反馈。
10. 完成训练后 PPL 推荐推进，已完成训练日的 A/B 方案切换。
11. 数据页出现训练历史和周统计。
12. “我的”页面可以导出备份，文件不包含 API Key。
13. 在 320×568、375×667、390×844 下页面没有横向溢出，动作名称和数字完整显示。
14. 正式训练主按钮始终位于底部导航上方，不下滑也可以操作；输入时虚拟键盘不遮挡当前数字。
15. 登录页和首页的本地主视觉图片可以加载；图片失败时仍可进入训练。
16. 导入仅包含个人档案、训练体系和历史记录的旧版备份后，系统自动补齐新增状态；训练体系正常显示且可以生成计划。
17. 兼容修复不得清除有效训练历史；进行中重量和次数刷新后仍可恢复。
18. “我的”页面直接显示个人档案与设置，不再出现“知识库”入口及占位内容。
19. 精选动作只在进入训练设置后加载；中文步骤只在首次展开时加载一次。
20. 新动作显示标签和中文步骤；替换只改变当前动作，且目标肌群和整套结构保持合格。
21. “不适”反馈会暂停推荐，可在“我的”恢复；“吃力”不自动换动作；“轻松”可选择继续进阶或换变式。
22. 版本 1 与版本 2 备份均能导入，动作偏好和动作库版本会随新版备份导出，API Key仍排除。

## 5. 常见问题

### AI 生成失败

系统应自动显示本地备用计划。若没有，检查浏览器控制台和 `createLocalPlan()`。

### 刷新后训练没有恢复

确认使用的是同一个本地用户名，并检查 `today_plan` 与 `active_training` 的计划 ID 是否一致。

### 数据丢失

数据默认只在当前浏览器。优先使用最近导出的备份恢复；API Key需要单独重新填写。

### 页面发布后仍是旧版

先确认 GitHub Pages 工作流成功，再强制刷新浏览器缓存。


## 6. 数据可靠性修复（2026-10-06）

本阶段只处理数据可靠性，不改变计划动作数量、器械过滤或部分训练的周期推进规则。

- 训练结束先保存可重试快照，再统一提交历史、周期、身体记录及训练清理。写入失败时回滚；写入中断时下次登录回滚。空间不足时不清理旧记录以腾空间。
- 保存失败页提供“重试保存”和“导出含本次训练的备份”。重试使用同一记录编号，不重复计入训练或推进周期。仅导出文件不会将本地训练标为已保存。
- 未完成训练不因日期变化而清空。进入时显示原计划日期，继续使用原动作和组记录。
- 不再截断训练历史、已有归档、体重或围度记录。已有 `sessions_archive` 保留并随备份导入导出，不自动并入当前历史列表；此前已被旧版本删除的记录无法凭空恢复。
- 导入 V1/V2 备份时先完整检查结构和数值，再保存操作前快照。导入期间切换用户会取消导入；中途失败回滚，回滚失败暂停后续写入并保留恢复日志。
- 本地坏 JSON、异常历史和训练状态先保存到 `compat_recovery`，正常记录继续使用；异常原文不参与统计。隔离快照无法保存时，不覆盖原文。
- “我的 → 本地数据备份”提供导入前快照恢复、撤销恢复、动作兼容前快照恢复和恢复资料导出。异常快照不能直接恢复时，先导出修正，不能强制覆盖。
- 普通备份包含未提交的当前训练与恢复资料；全局 API Key 不进入备份。`IronTrackRecovery` 文件用于检查隔离原文，不是直接覆盖导入的普通备份。
