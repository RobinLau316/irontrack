# IronTrack 运行与发布手册

更新日期：2026-10-08

## 1. 本地运行

```bash
npm run dev
```

打开 `http://127.0.0.1:4173/`。修改 `index.html` 后刷新浏览器即可看到变化。

## 2. 静态检查

```bash
npm run build
git diff --check
```

`npm run build` 不调用早期 Next.js 原型，当前依次检查：

- `index.html` 的脚本语法和关键功能标记。
- 精选动作库数量、字段、中文名称、动作模式、器械和默认训练量。
- 207 份中文步骤、91 个旧动作映射、资源体积和上游媒体排除边界。
- 本地备用计划的推拉腿、时长、动作目录约束和旧数据迁移；动态 AI 计划的安全候选、动作角色、时长/恢复总组数上限与重量校验。
- 主动切换训练日、预览取消不推进循环、确认后按实际训练日衔接，以及训练中切换先保存已确认组。
- 首次档案、PPL 迁移、计划/实际值分离、部分训练推进选择、保存失败重试和 V1/V2/V3 备份兼容。

阶段二已于 2026-09-03 发布并完成线上验收。以后涉及动作库版本或数据结构升级，仍须先导出现有备份再发布。

## 3. 浏览器冒烟测试

发布前至少验证：

1. 新建本地用户，进入训练页，逐题检查档案问题；中途刷新后回答仍保留。旧用户不重复出现问卷。
2. 训练准备只有三项必答问题：时间、疲劳、疼痛/不适；默认健身房。推/拉/腿可主动切换，当天重点是选填文本，不展开为额外问卷。
3. 有历史数据时直接从拉日切到推日，无需清除档案；生成预览、取消和重新选择均不推进循环，保存确认训练后从实际训练日正确衔接。
4. 不开启 AI、无 API Key 时也能生成并明确标注本地备用计划；30 分钟为 6 个动作，其余时间不超过 8 个。
5. 开启 AI 的模拟场景中，推日并填写“以胸部为重点”时主要训练体现胸部重点，辅助动作服务整体安排；普通推日不默认只练胸。模型可动态选择数量/构成但不超过 8 项，不受本地固定槽位限制。
6. AI 输入包含长期方向、近期实际组/反馈、时长、疲劳、不适和重点；改变时长或疲劳会影响动作/组数安排。无可核验重量时计划不臆造负重；无效返回会明确回退并允许重试。
7. 计划预览可用一句日常语言请求调整；AI 关闭或不可用时计划与输入保留，可继续手动换动作。
8. 计划值与实际值分别显示；每组重量和次数默认来自计划，只有点“完成本组”后才进入实际记录。
9. 刷新并重新登录同一用户，进行中动作、组记录、当前重量/次数及休息计时恢复；训练中改日先进入保存流程，失败仍可重试，返回训练不会丢组。
10. 跳过动作或提前结束后要求选择“继续这一天/推进到下一天”；数据页仅统计有已确认实际组的训练。
11. 训练结束只要求“轻松/刚刚好/偏吃力”，可以补充一句不适；保存失败显示重试和含本次训练的备份。
12. “我的”可更新训练方向、频率、经验和限制；AI 默认关闭，启用前清楚说明会发送给 DeepSeek 的训练资料；API Key 不进备份。
13. 旧分化计划迁入 PPL 时历史和进行中训练不被覆盖；导入 V1/V2/V3 备份均能通过校验。
14. 在 320×568、375×667、390×844 检查横向溢出、触控区域、安全区、底部训练按钮和键盘遮挡。
15. 动作中文说明按需加载；无需上游媒体或远程 GitHub 动作数据仍可完成训练。

## 5. 常见问题

### AI 生成失败

系统应自动显示本地备用计划。若没有，检查浏览器控制台和 `createLocalPlan()`。

### 刷新后训练没有恢复

确认使用的是同一个本地用户名，并检查 `today_plan` 与 `active_training` 的计划 ID 是否一致。

### 数据丢失

数据默认只在当前浏览器。优先使用最近导出的备份恢复；API Key需要单独重新填写。

### 页面发布后仍是旧版

先确认 GitHub Pages 工作流成功，再强制刷新浏览器缓存。


## 6. 数据可靠性修复（2026-10-06）

本阶段只处理数据可靠性，不改变计划动作数量、器械过滤或部分训练的周期推进规则。

- 训练结束先保存可重试快照，再统一提交历史、周期、身体记录及训练清理。写入失败时回滚；写入中断时下次登录回滚。空间不足时不清理旧记录以腾空间。
- 保存失败页提供“重试保存”和“导出含本次训练的备份”。重试使用同一记录编号，不重复计入训练或推进周期。仅导出文件不会将本地训练标为已保存。
- 未完成训练不因日期变化而清空。进入时显示原计划日期，继续使用原动作和组记录。
- 不再截断训练历史、已有归档、体重或围度记录。已有 `sessions_archive` 保留并随备份导入导出，不自动并入当前历史列表；此前已被旧版本删除的记录无法凭空恢复。
- 导入 V1/V2 备份时先完整检查结构和数值，再保存操作前快照。导入期间切换用户会取消导入；中途失败回滚，回滚失败暂停后续写入并保留恢复日志。
- 本地坏 JSON、异常历史和训练状态先保存到 `compat_recovery`，正常记录继续使用；异常原文不参与统计。隔离快照无法保存时，不覆盖原文。
- “我的 → 本地数据备份”提供导入前快照恢复、撤销恢复、动作兼容前快照恢复和恢复资料导出。异常快照不能直接恢复时，先导出修正，不能强制覆盖。
- 普通备份包含未提交的当前训练与恢复资料；全局 API Key 不进入备份。`IronTrackRecovery` 文件用于检查隔离原文，不是直接覆盖导入的普通备份。
