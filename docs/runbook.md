# IronTrack 运行与发布手册

更新日期：2026-10-15

## 1. 本地运行

```bash
npm run dev
```

打开 `http://127.0.0.1:4173/`。应用是静态单页，不需要构建服务端产物。

## 2. 发布前检查

```bash
npm run build
git diff --check
```

构建检查页面脚本语法、核心教练流程标记、备份兼容和 Service Worker 不加载旧动作库。真实 AI 请求与手机实机验收不由该检查代替。每次发布递增 `sw.js` 的 `CACHE_VERSION`。

## 3. 浏览器验收

新建一个隔离的本地测试用户和来源，避免触碰用户现有档案或进行中训练。需要真实 AI 请求时，只使用用户明确同意发送的测试资料，并由测试者提供有效 Key。

1. 首次打开：自由输入训练目标；回答草稿刷新后保留；无 API Key 时回答不丢失，并明确提示去设置 Key。
2. AI 了解用户：逐轮只问一个必要问题；不重复已知内容；档案中的默认样例数字不会被当作用户确认事实。检查用户理解摘要和阶段安排，确认前不完成首次设置。
3. 信息发送提示：发送前说明哪些训练信息将发送到 DeepSeek；未确认时不发请求，确认后可继续。姓名不进入提示内容。
4. 已有用户：先复用已保存档案和真实训练记录；兼容旧训练日、历史及本地备份；旧版进行中训练能继续，旧计划预览不会进入新动作流程。
5. 每日计划：仅询问当天情形和可用器械，用户可自由描述目标；不出现动作库加载、PPL 必选或旧本地模板回退。计划动作有通俗中文名、训练作用、分步骤教学、组数/次数/重量/休息；相同动作不重复。
6. 计划预览：自然语言微调尽量保留未提及内容；用户确认后逐组训练，取消不产生实际记录。动作教学在计划预览和训练中可读。
7. 逐组训练：每组只确认实际重量、次数；每组完成后不强制评分；刷新后恢复动作、组次、已确认记录和休息进度。
8. 训练结束：反馈文字可跳过；先保存真实记录，再显示 AI 复盘。实际记录不能被计划值替代。阶段目标或每周安排明显变化应等待用户确认；API 失败不得影响已保存训练。
9. 布局：检查 320×568、375×667、390×844 的横向溢出、安全区、底部导航、长动作教学和键盘遮挡。
10. 数据：使用导出的测试备份确认 V1/V2/V3 兼容；不得通过清除浏览器数据来修复问题。

发布前确认当前测试资料为合成资料，且 UI 验收没有修改用户已有资料。

## 4. 发布与线上核验

推送 `main` 后，等待 `.github/workflows/deploy-pages.yml` 成功，再打开[线上站点](https://robinlau316.github.io/irontrack/)，确认：

- 主 HTML 标题为“你的私人训练教练”。
- `public/app/coach.js` 和最新 CSS 可通过线上域名加载。
- `sw.js` 使用此次发布的新缓存版本，应用不再请求 `exercise-engine.js`、动作目录或中文步骤 JSON。
- 首页、教练引导、路线、历史和备份入口正常。

## 5. 已知限制

- AI 使用 DeepSeek Key。未设置 Key、连接失败或结果校验失败时，用户无法生成新 AI 计划；已保存训练和历史不受影响。
- 训练数据和 Key 只保存在当前浏览器；Key 不进入普通备份。
- AI 动作说明由文字生成，程序不能据此确认用户的现场动作质量。明显疼痛或异常症状应停止相关训练；应用不诊断伤病。
- 静态页面和合成数据验收不代表真实 DeepSeek 计划质量或 iPhone 主屏幕实机验收。
