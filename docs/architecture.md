# IronTrack 系统架构

更新日期：2026-09-02

## 1. 运行形态

IronTrack 当前是一个部署在 GitHub Pages 的单页静态应用。线上只发布 `index.html` 和 `public/`；早期 Next.js 原型保留在 `src/`，不参与当前部署。

应用没有自有后端。训练数据保存在浏览器 `localStorage`，AI 计划适配由浏览器直接请求 DeepSeek API。

V1.1 视觉层仍由同一个 `index.html` 提供，主视觉资源保存在 `public/`。本次改版没有改变本地存储键、数据结构或训练状态机。

登录后会先执行本地数据兼容检查：保留有效档案、计划、历史和进行中训练，同时为旧版本或旧备份缺少的周期轮换、核心锁定、训练阶段等字段补默认值。非空但结构无效的数据在替换前会保存一次兼容恢复快照。

精选动作库阶段一已经完成分类验收。`public/data/exercise-catalog.v1.json` 保存 207 个精简动作，`public/data/exercise-instructions-zh.v1.json` 保存对应中文步骤。阶段二已在本地入口接入 `public/exercise-engine.js`：目录只在进入训练设置时加载，中文步骤只在展开时加载。线上仍待用户备份后发布。

## 2. 核心模块

### 本地规则引擎

本地规则引擎负责：

- 根据已完成训练推进 PPL 周期。
- 选择 1～2 个核心动作。
- 按 A/B 阶段稳定轮换约 35% 的辅助动作。
- 根据训练时间生成 8～15 个动作。
- 根据环境、不适部位和避开动作过滤动作。
- 根据上次反馈提出加重、维持或减量建议。
- 按稳定编号过滤器械、不适、避开和暂停推荐动作，并校验同肌群替换与推拉腿结构。
- AI 或精选目录不可用时生成完整备用计划。

### AI 适配层

AI 接收本地规则生成的骨架、当天状态和最近记录，只能返回合格动作编号。结果必须通过程序校验：动作数量、锁定动作、同肌群替换、器械、暂停推荐、结构平衡和数值字段均须合规。首次结果不合规时重试一次；仍失败则使用本地计划。

### 计划预览

计划在开始前处于 `preview` 状态。用户可以锁定、替换同类动作，并修改组数、次数、重量和休息时间。确认后状态变为 `active`，训练过程中不再调用 AI。

### 训练状态机

主要状态为：

```text
生成前设置 → 计划预览 → 热身 → 正式训练 → 动作反馈 → 拉伸 → 完成
                              ↕
                           休息计时
```

每完成一组、切换动作、提交反馈或改变板块后，进行中训练写入本地存储。刷新后通过计划 ID 恢复当前动作、组数、记录和休息结束时间。

### 数据复盘

完成训练后保存计划来源、A/B 方案、实际组记录、目标、完成状态和动作反馈。数据页使用这些信息展示周统计、力量趋势和最近训练反馈。

## 3. 数据对象与存储键

按用户命名空间保存的主要键：

| 键 | 用途 |
|---|---|
| `profile` | 个人档案和器械 |
| `plan` | 当前训练模板 |
| `sessions` | 已完成训练历史 |
| `today_index` | 下一训练日索引 |
| `today_plan` | 今日计划及预览/执行状态 |
| `active_training` | 进行中训练快照 |
| `cycle_variants` | 推、拉、腿的下一轮 A/B 状态 |
| `core_locks` | 核心动作锁定状态 |
| `training_phase` | 4～6 周阶段起点和完成次数 |
| `setup_draft` | 生成前设置草稿 |
| `body_records` | 体重和体脂记录 |
| `measurements` | 围度记录 |
| `exercise_preferences` | 暂停推荐动作与“继续进阶/换变式”偏好 |
| `exercise_catalog_version` | 当前已完成兼容处理的动作库版本 |

API Key 使用独立的全局键 `irontrack_global_apikey`。它不进入普通备份。

## 4. 备份

备份格式包含应用标识、格式版本、用户标识、导出时间和用户数据。导入前校验格式并保存导入前快照；新设备恢复后需要重新填写 API Key。

## 5. 设计边界

- 单机、单人是主要使用场景。
- 当前没有云同步、自有数据库或服务端密钥保护。
- 浏览器直连 AI 意味着密钥只能做到本机保存，不能视为服务端安全存储。
- 身体不适信息只用于排除或降低相关训练，不用于诊断。
- 精选动作数据与说明可以本地发布，但不得复制或运行时加载上游图片、GIF 和 Gym visual 媒体。
- 完成发布和线上验收前，不能把本地阶段二实现描述为已经在线生效。
