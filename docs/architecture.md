# IronTrack 系统架构

更新日期：2026-10-15

## 1. 运行形态

IronTrack 是部署在 GitHub Pages 的单页静态应用，没有自有后端。训练档案、教练总结、阶段规划、历史和进行中训练保存在浏览器 `localStorage`。早期 Next.js 原型保留在 `legacy/`，不参与部署。

`index.html` 依次加载 `core.js`、`data.js`、`helpers.js`、`plan.js`、`pages.js`、`training.js`、`coach.js` 和 `boot.js`。`coach.js` 提供当前产品流程并复用旧版经过验证的存储、训练状态机、记录与备份逻辑。Service Worker 预缓存应用壳；每次发布必须递增 `CACHE_VERSION`。

新训练流程不加载旧开源动作库、动作引擎或动作说明 JSON。历史计划和记录里可能仍有旧动作编号与名称；这些字段留在本地数据中供历史展示和兼容，不参与新计划生成。旧动作文件暂留仓库归档，不在页面或 Service Worker 清单中请求。

## 2. 教练流程

### 首次了解与阶段安排

首次进入由 `renderOnboarding()` 发起自由对话。`sendCoachIntake()` 将用户回答与其已确认档案、训练记录交给 DeepSeek，逐轮补问并形成摘要。用户确认教练理解后，生成第一阶段安排；用户可以微调后再确认。草稿保存在 `onboarding_draft`，档案摘要、事实字段和阶段安排保存在 `profile`。已有用户优先复用原档案和历史，再补充教练理解。

### 当天计划

`renderTrainingSetup()` 只收集当天状态、器械条件和用户自由补充。`generateTodayPlan()` 直接调用 AI，根据确认的阶段安排、档案、当天信息和近期真实完成记录生成计划；不会先生成固定动作模板。返回内容必须包含可读名称、训练目标、组数/次数/建议重量、休息和通俗步骤，并经数量、数值、重复名称、教学步骤、时间总量和历史重量检查后才能预览。AI 失败时不显示本地旧模板，也不谎称生成成功；用户可以重试，旧历史保持不变。

### 逐组带练和复盘

`training.js` 提供可恢复的逐组训练状态机；`coach.js` 覆盖新训练的预览、教学、组完成和结束复盘入口。每组只保存用户确认的实际重量与次数。单次训练反馈是选填文字。训练保存后，教练读取阶段安排和真实历史形成短复盘；日常微调由教练继续处理，阶段目标或每周安排显著变化以待确认建议保存。

## 3. AI 与隐私

浏览器使用本机配置的 DeepSeek API Key 直连服务。首次发送前会提示用户：训练档案、身体限制、当天情况与近期实际训练记录会发送给 DeepSeek，用于对话、计划和复盘；姓名不会发送。用户确认后将该授权状态保存在本地。API Key 使用独立全局键，不进入普通备份。AI 生成前仍须提供明确失败提示；训练数据先保存成功，再请求 AI 复盘。

动作文字教学由 AI 生成，程序要求至少两条步骤并展示其作用说明；该内容不能证明教练实际观察到用户动作。程序不作医疗诊断。

## 4. 旧数据和备份

应用继续兼容 `profile`、`plan`、`sessions`、`today_plan`、`active_training`、`training_phase` 等既有键，以及 V1/V2/V3 备份。旧版进行中的训练优先恢复并允许完成；旧预览计划会在进入新流程时丢弃。用户确认的历史实际组、归档、身体数据和恢复快照不因本次改版清除。

当前新增的 `profile` 属性保存教练摘要、确认事实、阶段安排、训练授权和最近复盘；`onboarding_draft` 保存首次对话进度；`setup_draft` 保存当天输入。未知属性由旧版兼容层原样保留。

## 5. 发布边界

- 推送 `main` 触发 GitHub Pages 工作流。
- 发布前运行 `npm run build`、`git diff --check`，核对 Service Worker 缓存版本。
- 浏览器无 API Key、AI 调用失败、训练保存失败、旧进行中训练恢复和移动端页面需要分别说明验证结果。静态检查不代表真实 AI 或 iPhone 验收。
- 训练数据只存本机；用户应定期从“我的”导出备份。
