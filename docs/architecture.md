# IronTrack 系统架构

更新日期：2026-10-08

## 1. 运行形态

IronTrack 当前是一个部署在 GitHub Pages 的单页静态应用。线上只发布 `index.html` 和 `public/`（脚本按加载顺序拆分在 `public/app/`）；早期 Next.js 原型保留在 `legacy/`，不参与当前部署。

应用没有自有后端。训练档案、计划、历史和进行中训练保存在浏览器 `localStorage`。用户可选择启用 AI 计划适配；启用后浏览器把训练方向、当天回答和近期实际记录直接发给 DeepSeek，不发送姓名。

根目录 `sw.js` 注册 Service Worker：预缓存应用壳与动作数据，页面和数据 JSON 走网络优先（失败回退缓存），静态资源走缓存优先。每次发布必须递增 `CACHE_VERSION`，旧缓存在激活时清除。历史和既有归档不自动截断，并随备份导出。

V1.1 视觉层仍由同一个 `index.html` 提供，主视觉资源保存在 `public/`。2026-10-08 流程改版增加档案字段与备份 V3 迁移，并将训练结束反馈纳入状态机。

登录后会先执行本地数据兼容检查：保留有效档案、计划、历史和进行中训练，为旧版本缺少的档案与运行字段补默认值，并在没有进行中训练时把旧分化映射为 PPL。非空但结构无效的数据在替换前会保存兼容恢复快照。

精选动作库阶段一已经完成分类验收。`public/data/exercise-catalog.v1.json` 保存 207 个精简动作，`public/data/exercise-instructions-zh.v1.json` 保存对应中文步骤。阶段二已接入 `public/exercise-engine.js` 并上线：目录只在进入训练设置时加载，中文步骤只在展开时加载。

## 2. 核心模块

### 本地规则引擎

本地规则引擎负责：

- 根据已完成训练推进 PPL 周期。
- 根据训练时间生成 6～8 个动作，30 分钟为 6 个，其余为 8 个。
- 默认健身房，不再让用户选择器械和环境；身体不适时保守避开相关动作。
- 根据实际完成的重量、次数、组数、动作反馈及当天疲劳建议维持或小幅调整。
- 按稳定编号过滤器械、不适、避开和暂停推荐动作，并校验同肌群替换与推拉腿结构。
- AI 或精选目录不可用时生成完整备用计划。

### AI 适配层

AI 默认关闭。用户在“我的”明确开启并填写 API Key 后，AI 接收脱敏训练档案、当天状态、近四次同类训练的实际组记录和本地计划骨架。AI 只能在本地允许的同训练部位/模式动作中选择，并受动作数、重量变化和训练结构校验限制；网络失败或结果不合规时保留本地计划。

### 计划预览

计划在开始前处于 `preview` 状态。用户可以用日常语言请求调整、替换动作，并修改组数、次数和重量。确认后状态变为 `active`；开始后不再调用 AI。

### 训练状态机

主要状态为：

```text
首次档案（新用户）→ 当日三问 → 计划预览/调整 → 确认 → 热身 → 正式训练 → 动作反馈 → 结束反馈 → 保存
                              ↕
                           休息计时
```

每确认一组、切换动作、提交反馈或改变板块后，进行中训练写入本地存储。刷新后通过计划 ID 恢复当前动作、组数、记录和休息结束时间。训练结束先询问整体感受；若未完成计划组数，用户选择下次继续这一天或推进到下一天。保存失败时保留待保存快照供重试。

### 数据复盘

训练记录保存目标组数、次数、重量与每组确认后的实际重量/次数，并标记完成、部分完成、跳过或未开始。周完成次数和连续训练天数只计完整训练；部分组仍留在历史与 AI 的实际表现上下文中。未确认目标不计入完成记录；不再用跨器械可比性较弱的总重量容量作为主要指标。训练不会自动伪造体重记录。

## 3. 数据对象与存储键

按用户命名空间保存的主要键：

| 键 | 用途 |
|---|---|
| `profile` | 训练方向、频率、经验、限制、档案备注及 AI 开关（旧身体数据字段保留） |
| `plan` | 当前训练模板 |
| `sessions` | 完整、部分及未完成训练记录 |
| `today_index` | 下一训练日索引 |
| `today_plan` | 今日计划及预览/执行状态 |
| `active_training` | 进行中训练快照 |
| `cycle_variants` / `core_locks` | 旧版本兼容字段，当前界面不显示 |
| `training_phase` | 训练阶段起点和完整训练次数 |
| `setup_draft` | 生成前设置草稿 |
| `onboarding_draft` | 首次档案问答的断点草稿 |
| `body_records` | 体重和体脂记录 |
| `measurements` | 围度记录 |
| `exercise_preferences` | 暂停推荐动作与“继续进阶/换变式”偏好 |
| `exercise_catalog_version` | 当前已完成兼容处理的动作库版本 |

API Key 使用独立的全局键 `irontrack_global_apikey`。它不进入普通备份。

`BACKUP_VERSION` 为 3；导入兼容版本 1、2、3。API Key 继续使用独立的全局键并排除在备份之外。

## 4. 备份

备份格式包含应用标识、格式版本、用户标识、导出时间和用户数据。导入前校验格式并保存导入前快照；新设备恢复后需要重新填写 API Key。

## 5. 设计边界

- 单机、单人是主要使用场景。
- 当前没有云同步、自有数据库或服务端密钥保护。
- 浏览器直连 AI 意味着密钥只能做到本机保存，不能视为服务端安全存储。
- 身体不适信息只用于排除或降低相关训练，不用于诊断。
- 精选动作数据与说明可以本地发布，但不得复制或运行时加载上游图片、GIF 和 Gym visual 媒体。
- 精选动作库升级必须继续遵守固定版本、人工复核、兼容快照和线上验收流程。
